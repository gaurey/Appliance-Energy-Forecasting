# Appliance Energy Forecasting — Time Series Case Study

A full time-series forecasting case study on the UCI **Appliances Energy Prediction**
dataset (Candanedo, Feldheim & Deramaix, 2017): benchmark models, SARIMA/SARIMAX,
a feature-based ML model (XGBoost), and a time-series foundation model, evaluated
consistently on a 24-hour-ahead forecasting task.

## Problem

Forecast **hourly appliance electricity use (Wh)**, 24 hours ahead, for a low-energy
residential house, using its own history plus indoor sensor and outdoor weather data.

## Reproducing the results

The notebook is fully self-contained: it does not import from `src/` and can be run from
any folder — it creates `data/`, `figs/` and `results/` next to itself and downloads the
raw dataset automatically if it isn't already present.

```bash
pip install -r requirements.txt
jupyter nbconvert --to notebook --execute --inplace notebooks/analysis.ipynb
# or just open notebooks/analysis.ipynb and Run All
```

Some SARIMA/SARIMAX cells take 1–3 minutes each to fit — this is expected. The `src/`
modules are kept in the repository as the original, stage-by-stage reference implementation
(useful for re-running just one part from the command line, e.g. `python src/part4_sarimax.py sarima`), but the notebook itself no longer depends on them.

**Note on the SARIMAX+exogenous model:** its optimiser does not converge to a single stable
value across repeated fits (observed RMSE range: ~175–225 Wh), even though every other model
in this study reproduces exactly. This is documented in the notebook and report rather than
hidden — the qualitative finding (exogenous variables make this particular model worse than
the seasonal-only SARIMA) held in every run performed.

## Method summary

| Stage | Approach |
|---|---|
| Data | 10-min readings binned to hourly (energy summed, sensors averaged) |
| EDA | Decomposition (24h & 168h), ACF/PACF, ADF + KPSS stationarity tests |
| Benchmarks | Mean, Naive, Daily/Weekly seasonal naive, Drift — rolling-origin, 24h horizon |
| SARIMA/X | AIC grid search p∈[0,6] d∈[0,2] q∈[0,6]; seasonal term s=24; optional weather/hour exogenous regressors |
| ML | XGBoost with lag (≥24h, leakage-safe), rolling-window, calendar, and lagged-weather features; feature-group ablation |
| Foundation model | Genuine Chronos load attempt (fails: no huggingface.co access, broken local CUDA); Holt-Winters used as a documented, transparent substitute |
| Evaluation | RMSE, MAE, MAPE, sMAPE; rolling-origin (14 origins) for benchmarks/ML/foundation model; single origin for SARIMA/X (documented computational-cost trade-off) |

## Key results (see `report.docx` for full discussion)

- The **level series is already stationary** by both ADF and KPSS, despite pronounced daily/weekly seasonal structure.
- **Seasonal SARIMA** (RMSE ≈137 Wh) is the strongest model tested, a >2.5x improvement over the best non-seasonal ARIMA.
- Adding **exogenous weather regressors made SARIMAX worse** (RMSE ≈175 Wh) — and even that result is a conditional, not a true, forecast (uses actual future weather).
- **XGBoost**, restricted to strictly leakage-safe (≥24h) features, only modestly beats the naive benchmarks (RMSE ≈405 Wh) — most of its signal comes from lags and calendar features, not weather.
- The **foundation-model stage could not run a genuine pretrained model** in this sandboxed environment (no huggingface.co access; broken local CUDA) — this limitation, and its practical deployment implications, is discussed explicitly rather than hidden.
